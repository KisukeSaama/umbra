# Audit of Umbra, 10 September 2026

Read-only review of the whole application at commit `75f27f4`: security,
compliance with the product rules in `AGENTS.md` and `docs/product.md`, the
domain and data layer, jobs, providers, the front end and the documentation.
Every finding below was checked against the code; line numbers refer to that
commit. Nothing was changed as part of the audit.

## The short version

The codebase is in good shape: the architecture described in the docs is the
one in the code, every third-party call goes through Janus, uniqueness lives in
the database, the storage explorer is carefully contained, the authorisation
model matches ADR 0009, and the i18n design is solid. The problems are
concentrated in a few places, and one of them is serious.

Fix in this order:

1. **Critical.** `AUTO_APPROVE_MEMBERS=false` is parsed as `true`, so the
   approval gate is off in production. One line in `src/lib/env.ts`.
2. **High.** The scheduled disk walk runs once and never again.
3. **High.** Requests have no state machine: any status can move to any other.
4. **High.** Acknowledging a report on a re-cut starts tracking the original
   series and opens one task per episode of a calendar the server does not hold.
5. **High.** The Drizzle schema, with the ORM, is shipped to the browser through
   the announcement form.
6. **High.** Cmd/Ctrl+K opens two search dialogs on the home page.

Then the Medium items: the Plex paging termination that can wipe a section from
the index, the enrichment pass that can starve, publishing a draft that notifies
everyone with an empty title, and the missing transactions around multi-step
writes.

## Findings

Severity: Critical means a product rule or security boundary is off in
production today; High means a visible malfunction or a real bundle or
accessibility defect; Medium means wrong behaviour under conditions that will
occur; Low means hygiene, robustness or polish.

### Critical

**C1. Boolean environment flags are parsed with `z.coerce.boolean()`.**
`src/lib/env.ts:30` and `:35`. Zod's coercion is `Boolean(input)`, so the
strings `"false"` and `"0"` become `true`. Verified against the installed zod:
`z.coerce.boolean().parse("false") === true`. The pipeline writes the literal
string `AUTO_APPROVE_MEMBERS=false` (`.gitlab-ci.yml:122`, `deploy/app.env:20`,
`.env.example:29`) and `deploy/compose.yml:30` passes it to the container.
`src/lib/auth/session.ts:217` and `:241` then create every new account as
`approved` instead of `pending`. Anyone with a free Plex account is a member on
first sign-in, with search, requests, reports, votes and the SSE stream. The
same flaw affects `DEV_LOGIN`; only the `NODE_ENV` guard at
`src/app/api/auth/dev-login/route.ts:31` keeps that route out of production.

Fix: `z.stringbool()` for both flags (verified: `z.stringbool().parse("false")
=== false`), plus a test in `tests/env.test.ts` asserting that `"false"` parses
to `false`. Then check the accounts table in production for members approved
without a decision.

### High

**H1. The scheduled storage scan runs exactly once.** `src/lib/jobs/index.ts`
`runJob` stamps `job_state.last_success_at` on every success (`:104-114`), and
the `storage-scan` step returns `0`, which is a success, when `due()` says it is
not due (`:309-314`). Thirty minutes after the first walk the stamp is refreshed
again, so `due("storage-scan", 6h)` is false forever. Only the manual button
walks the tree again. `docs/architecture.md` promises a six-hour cadence.
Fix: decide `due()` outside `runJob` and skip the call entirely, or stamp
`last_success_at` only when the step did the work.

**H2. Requests have no transition table.** `src/lib/domain/requests.ts:308-356`
and `src/app/api/admin/requests/[id]/route.ts:18-21` accept any of the five
statuses from any status. Reports check `canTransition`; requests do not.
`rejected` to `requested` or `accepted` raises a unique violation on
`media_request_active_idx` when a member has re-requested the title in the
meantime, and it is not caught here, so the administrator gets a 500.
`available` to `requested` re-notifies the member and hands a fulfilled title
back to the queue. Fix: a `REQUEST_TRANSITIONS` table next to
`src/lib/reports/reasons.ts`, checked before the update and repeated in the
`WHERE` clause.

**H3. Acknowledging a re-cut report tracks the original series.**
`src/lib/domain/reports.ts:534-541` calls `trackSeries` for any report on a
`tv` title. A re-cut the server matched to nothing carries the provider id of
the original series (`cut_provider_id`), `linkSeriesToLibrary`
(`src/lib/domain/series.ts:312-323`) matches on `l.tmdb_id` only, so
`plex_rating_key` stays null, `reconcileEpisodes` (`:152-173`) marks every
aired episode `aired_missing` and opens one task per episode. "Naruto Kai"
acknowledged with `series_outdated` yields hundreds of tasks for a numbering
that does not exist, and the report can never self-close because
`closeReportsSolvedByCalendar` needs `plex_available = TRUE`. This contradicts
`docs/product.md` ("a re-cut has no calendar to be late on"). Fix: skip
`trackSeries` when `alternateCutFor(...)` is non-null, and give cut reports a
closing rule of their own or state that they close by hand.

**H4. The Drizzle schema is in the client bundle.**
`src/components/admin/announcement-form.tsx:23-26`, a `"use client"` file,
value-imports `ANNOUNCEMENT_CATEGORIES` from `@/lib/db/schema`, which imports
`drizzle-orm` and `drizzle-orm/pg-core`. Confirmed in the build: a 114 KB
client chunk contains `PgTable` and the index names of the schema. Fix: move
`ANNOUNCEMENT_CATEGORIES` and its type to a dependency-free module, import it
from `schema.ts`, and add `import "server-only"` to `schema.ts` so it cannot
recur.

**H5. Two search palettes on the home page.** `src/components/site-header.tsx:68`
and `src/components/home/hero.tsx:73` each mount a `CommandPalette`, and each
instance registers its own global `keydown` listener
(`src/components/command-palette.tsx:57-66`). On `/` the shortcut opens both
dialogs; Escape closes only the top one. Fix: one listener and one dialog; the
hero variant becomes a trigger that opens the header instance.

### Medium

Security and operations:

- **M1. CSP allows `'unsafe-inline'` scripts** (`next.config.ts:17`). No sink
  exists today, so this is defence in depth only, but the policy would not
  mitigate a future XSS. Next 16 supports nonces through `proxy.ts`.
- **M2. Open SSE streams per account are unbounded**
  (`src/app/api/notifications/stream/route.ts:40`, `src/lib/realtime.ts:82-98`).
  Opens are limited to 30 per minute, but nothing caps how many stay open; each
  holds an interval and a listener and costs two queries per nudge. Cap at a
  handful per account and close the oldest.
- **M3. Overlap protection between the worker and the admin button is
  check-then-act** (`src/app/api/cron/sync/route.ts:30-32`,
  `src/app/api/admin/jobs/run/route.ts:19-25`). `STALE_AFTER_MS` is 45 minutes
  and a full cycle can exceed it on a large library, at which point a second
  cycle starts over the first and marks it interrupted. Fix: a partial unique
  index `job_run(job_name) WHERE status = 'running'`, or `pg_try_advisory_lock`
  around the cycle.

Domain and data:

- **M4. Plex paging can stop early, and the sweep then deletes the rest.**
  `src/lib/providers/plex.ts:120-129` breaks when the parsed batch is shorter
  than the page size, but the batch is measured after `itemsFrom` dropped rows
  without `type`, `ratingKey` or `title`; one dropped row on a full page ends
  the walk. `MAX_PAGES * PAGE_SIZE` also caps a section at 40,000 entries. Since
  `sectionItems.length > 0`, the sweep in `src/lib/domain/library.ts:102-111`
  removes every unseen item, taking presence, season ladders and report
  auto-closing with them until a later run. Fix: break on the raw container row
  count or on `MediaContainer.totalSize`, and treat reaching `MAX_PAGES` as an
  error rather than a complete listing.
- **M5. The episode sweep is gated on shows, not on episodes**
  (`src/lib/domain/library.ts:85-111`). An empty `allLeaves` answer while Plex
  is mid-scan deletes every episode of the section while keeping its shows.
  Gate the sweep per kind.
- **M6. `reconcileEpisodes` only ever flips `plex_available` to true**
  (`src/lib/domain/series.ts:134-161`). An episode deleted from the server stays
  available forever: no task reopens, the gap index never reports it, and a
  `series_outdated` report may auto-resolve against a calendar that says
  everything is present. Add the reverse statement.
- **M7. The enrichment pass can starve.** `src/lib/domain/library.ts:240-272`
  leaves `poster_path` null when TMDB has no poster, and the selection is
  `poster_path IS NULL OR ...` newest first with `limit 120`. Once 120
  poster-less titles are newer than the unfilled ones, the same rows are fetched
  every cycle and older rows never get genres or scores, which the picker and
  the taste profile read. Stamp "enriched at" or a sentinel and exclude it.
- **M8. Publishing a draft notifies everyone with an empty title.**
  `src/app/admin/announcements/page.tsx:138` sends `PATCH { published: true }`
  alone; `src/lib/domain/announcements.ts:239-255` then calls
  `announceToEveryone(id, input.title ?? "", input.category ?? "information")`.
  Read title and category from the row the function already selects.
- **M9. Unpublishing a note does not close its poll**, and `activePoll` never
  joins `announcement.published` (`src/lib/domain/announcements.ts:196-257`,
  `src/lib/domain/polls.ts:38-53`). The poll stays active, visible on the home
  page and votable, with no note behind it.
- **M10. Status changes call the provider between the write and the
  notification without a transaction** (`src/lib/domain/requests.ts:334-354`,
  `src/lib/domain/reports.ts:518-543`). If TMDB is down, the request is
  `accepted` in the table, the administrator sees a 502, the series is not
  tracked and the member is never told. Same shape for announcement plus poll
  plus options plus fan-out (`announcements.ts:166-194`), `attachPoll`
  (`polls.ts:193-215`) and `setPollActive` (`polls.ts:231-246`), which
  deactivates every poll before activating the target. The only transaction in
  the codebase is in `taste.ts:66`.
- **M11. Concurrent report moves are last-write-wins**
  (`src/lib/domain/reports.ts:505-527`): the transition is checked on a read,
  then the update is `WHERE id = ?` only. Add `status = current.status` to the
  `WHERE` and answer 409 on zero rows.
- **M12. `syncSeriesEpisodes` never deletes episodes the provider removed or
  renumbered**, and overwrites `enabled` with `isRunning(details)` on every
  sync, undoing an administrator's manual enable; `seriesDueForSync` picks
  `enabled = true` only, so a disabled running show is never refreshed again
  (`src/lib/domain/series.ts:49-57, 65-118, 326-343`).
- **M13. Admin lists are unbounded** (`listRequests`, `listReports`,
  `listAccounts`, announcements, series: `src/lib/domain/requests.ts:162-186`,
  `reports.ts:364-375`, `accounts.ts:31-43`, `announcements.ts:137-155`,
  `series.ts:254-293`) and each row mounts client action buttons. `paginate()`
  and `Pagination` already exist; apply them, or separate live rows from a paged
  history.

Front end:

- **M14. Hard-coded English page titles**: `src/app/(site)/activity/page.tsx:31`,
  `discover/page.tsx:17`, `news/page.tsx:32`, `pending/page.tsx:9`,
  `sign-in/page.tsx:10`, and `src/app/layout.tsx:37` (description). The title
  page and every admin page export no metadata at all. Replace with
  `generateMetadata()` reading the translator, with keys in both dictionaries.
- **M15. The title page lacks the back link and back-to-top its skeleton
  promises**: `title/[kind]/[id]/loading.tsx:18` renders `BackLink`, the page
  does not, and `BackToTop` is used nowhere. The link disappears when the page
  lands. `docs/DESIGN.md` requires both.
- **M16. Command palette has no keyboard model beyond Tab**
  (`src/components/command-palette.tsx:184-250`): no arrow keys, no Enter, no
  `role="listbox"`, no result count announcement.
- **M17. Unread notifications are invisible to assistive technology**
  (`src/components/notification-bell.tsx:159-177`): constant trigger label,
  `aria-hidden` dot, and a live region that only exists while the menu is open.
- **M18. The admin drawer manages no focus** (`src/components/admin/admin-shell.tsx:155-200`):
  `role="dialog" aria-modal` without focus move, trap or restore. Build it on
  the existing `Dialog` primitive.
- **M19. The "requested" pill on a card reads as a call to action**
  (`src/components/title-card.tsx:76-83` shows `status.request`, "Request" /
  "Demander", for a title already requested). Add a `status.requestedShort`
  key.

### Low

Security:

- **L1.** `[id]` route params are not validated as UUIDs (`requests/[id]`,
  `reports/[id]`, `polls/[id]/vote`, every `admin/*/[id]`); a non-UUID makes
  Postgres throw and is logged as an unexpected 500. Use `z.uuid()` through a
  shared helper.
- **L2.** `POST /api/auth/plex/claim` is rate limited by the caller-chosen
  `pinId` only (`claim/route.ts:26`); add an address bucket and a global cap as
  the pin route does.
- **L3.** Admin write routes have no rate limit, including `POST /api/admin/series`
  (a TMDB calendar pull) and `storage/files/weigh` (walks up to 50,000 files).
- **L4.** Root-level non-library directories are hidden from listing
  (`storage-rules.ts:27-34`) but `locate()` accepts them as `path[0]`, so an
  administrator can delete inside `data` or `.trash` by crafting the request.
  Refuse `path[0]` when it is not a library.
- **L5.** No cap on open sessions per account, no rotation, fixed 30-day
  lifetime (`session.ts:39-61`).
- **L6.** `POST /api/cron/sync` is reachable through Traefik although only the
  worker on the internal network calls it. Exclude `/api/cron` at the router.
- **L7.** `deleteStorageEntries` batch limit is really 32, not 200:
  `assertNames` throws on `names.length > MAX_DEPTH` before the `MAX_BATCH`
  check (`storage-files.ts:247-248`). Functional, not security.
- **L8.** `ilike` patterns are not escaped (`library.ts:325`): `%` lists the
  newest titles. Parameterised, so bounded and harmless, but worth escaping.
- **L9.** `upsertAccountFromPlex` is select-then-insert with no unique violation
  catch (`session.ts:197-243`); two simultaneous first sign-ins of one account
  give one a 500. `dev-login` already uses `onConflictDoUpdate`.

Data and jobs:

- **L10.** Pool has no `connect_timeout`, `idle_timeout` or `statement_timeout`
  (`src/lib/db/index.ts:20`); one hung query holds a connection forever and the
  SSE route draws from the same pool of 10.
- **L11.** Missing indexes for queries that run every cycle or page load:
  `library_item(section_key, synced_at)` for the sweep, a partial
  `job_run(job_name) WHERE status = 'running'` for `anyJobRunning`,
  `media_request(requested_by, created_at)` for the follow-up and discover
  pages. `failingJobCount` runs a window function over the whole `job_run`
  table on every admin page load.
- **L12.** Migrations run on every boot without an advisory lock; fine for one
  container, worth documenting.
- **L13.** `settledAsksFor` excludes episode-level asks and `settledIndex` does
  not (`src/lib/domain/settled.ts:64` versus `:100-126`), so search and title
  page can disagree after a single-episode ask is resolved.
- **L14.** The "two clicks at the same instant get one report and two
  followers" claim in `createReport` (`reports.ts:72-74, 140-177`) does not
  hold under READ COMMITTED: the loser's CTE reads a snapshot from before the
  winner committed, so the second member gets 409 and is not following.
- **L15.** Two definitions of "aired": the UI pins a date to noon UTC
  (`seasons.ts:40-46`, `format.ts:45-47`), the database uses
  `air_date <= CURRENT_DATE` in the server's zone (`series.ts:159`,
  `reports.ts:658`). Until noon UTC on air day the page says scheduled while a
  task is already open.
- **L16.** `scripts/sync-worker.mjs:13-15, 52`: an empty or malformed
  `SYNC_INTERVAL_MINUTES` gives `0` or `NaN`, and `setTimeout(fn, NaN)` fires
  immediately, so the worker becomes a tight loop against the sync route.
- **L17.** `library-sync` bundles seven operations in one `runJob`
  (`jobs/index.ts:255-268`); a failure in enrichment or cut linking after a
  successful sync withholds `last_success_at` and stretches the settled-ask
  window in `settled.ts:43-46`.
- **L18.** `ensureMedia` overwrites `media.title` with the requester's language
  on every write (`requests.ts:85-86`, `catalog.ts:517-546`); the admin queue
  and other members' notifications flip language with the last writer.
- **L19.** `maxDuration = 300` on the cron route is a Vercel-only knob and does
  nothing under `next start`.
- **L20.** `episode_available` is a notification kind that is never emitted;
  `LIBRARY_KINDS` `season` is never written but is branched on.

## What is done well

- Authorisation is exactly ADR 0009: `requireMember`, `requireStaff`,
  `requireAdmin`; accounts route is admin-only, refuses self, refuses
  `role: "admin"`, blocking revokes sessions; single admin is a partial unique
  index. Every page calls its own guard, not only the layout.
- Every member mutation is scoped by `account_id` inside the SQL itself, so
  there is no IDOR. No `sql.raw` anywhere; every `sql` template is
  parameterised.
- Markdown is parsed to typed nodes and rendered as React elements: no
  `dangerouslySetInnerHTML`, `safeHref` refuses `javascript:` and
  protocol-relative links, announcement links are zod-restricted to http(s).
- Session cookie is `HttpOnly`, `SameSite=Lax`, `Secure` in production, with a
  SHA-256 digest stored; sign-in pins are opened server-side and consumed once;
  the Plex token is used once and never stored; secrets compared in constant
  time.
- CSRF is layered: `Sec-Fetch-Site` first, `Origin` against
  `X-Forwarded-Host`, applied to every unsafe method under `/api` by
  `proxy.ts`. Every body and query goes through zod; provider ids are digits
  only; `images.remotePatterns` pins the optimiser to TMDB.
- The storage explorer is the best-guarded code in the repository: names
  refused on separators and dots, lexical plus `realpath` containment, `lstat`
  at every hop, links never followed, deletion refused at the volume root,
  tested against a real temporary tree.
- Containers run as uid 10001, read-only, all capabilities dropped, worker and
  database on an internal network, secrets written with `umask 077`.
- Uniqueness genuinely lives in the database: partial unique indexes for live
  requests, live reports (with the `coalesce` trick), votes, the single admin
  and notification dedup keys; `createReport` and `withdrawReport` are single
  statements; fan-outs use `INSERT ... SELECT ... ON CONFLICT DO NOTHING`.
- Schema and migrations do not drift: the latest snapshot matches `schema.ts`
  column for column, index for index. All timestamps are `timestamptz`.
- Providers parse defensively (both Plex attribute shapes, single versus array
  containers, numeric id guards) and are the best-tested part of the code.
- The i18n design is unusually solid: flat typed keys, `fr` typed against `en`,
  `.one` variants for every counted key, `messageKey` errors resolved on the
  client, `Accept-Language` parsed with q-values and a cookie override.
- Clean server and client boundaries, `Promise.all` where calls are
  independent, `Suspense` around shelves, skeletons shaped like their content,
  reduced motion honoured, dialogs and menus on Base UI primitives with real
  focus handling, every mutation button disabled while pending.

## Test coverage

Tests cover the pure rules well (moods, report reasons, availability, seasons,
cuts, csrf, rate limit, pagination, markdown, storage files against a real
temporary directory, Plex and TMDB parsing). No test touches a database or a
